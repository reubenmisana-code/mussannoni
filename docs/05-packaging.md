# Packaging

This repository is two things at once, and keeping them apart is what makes the package
installable.

| | Workshop | Package |
| --- | --- | --- |
| Lives in | `tools/`, `templates/`, `corpus/`, `extract/`, `output/` | `src/mussannoni/` |
| Purpose | Measure a reference PDF and reproduce it exactly | Render a report from application data |
| Paths | Repository-root relative (`tools/common.py` `ROOT`) | Packaged resources via `importlib.resources` |
| Default engine | `chromium` — every calibration was measured against it | `weasyprint` — the only engine `pip` can install |
| Dependencies | `+ httpx, lxml, pillow, pyyaml, scikit-image` (the `workshop` extra) | `jinja2, pymupdf, weasyprint` |
| Input | `templates/<level>/<report>/fixture.json` | a caller's `dict` |

The two share the code that matters: `tools/render.py` imports its engines from
`mussannoni.engines` and its recompression pass from `mussannoni.optimize`, so there is one
implementation of each and a fix lands in both at once.

## Why the runtime cannot use the repository layout

`tools/common.py` derives every path from `ROOT = Path(__file__).resolve().parents[1]`, the parent
of the `tools/` package. In a checkout that is the repository root. In a `site-packages` install it
is `site-packages` itself, so `catalog/`, `templates/`, `corpus/` and `output/` would all be looked
for in the wrong place. Rather than make that function cope with both worlds, the runtime does not
call it: `mussannoni/resources.py` reads only what was copied into the package at build time.

## What ships, and what does not

Generated by `make package-resources` into `src/mussannoni/resources/`:

```
template.html                       one copy; all 46 per-report templates are byte-identical
reports.json                        the registry, distilled from catalog/reports.yaml
_shared/reset.css                   page box, table primitives, kerning suppression
_shared/fonts/                      base-14 exports + Liberation faces (the fallbacks)
<level>/<report>/report.css         measured @page size, .tN text classes, .fN cell fills
<level>/<report>/fonts/             the faces that report embeds
<level>/<report>/layout.json        the distilled layout the table API places data onto
```

Deliberately excluded:

Everything else stays in git and is regenerated from a checkout. Nothing below is in either
artifact:

| Excluded | Size | Why |
| --- | --- | --- |
| `templates/**/fixture.json` | 257 MB | Measured geometry for one sample unit each. Sample data, not code, and no caller could author it. |
| `extract/` | 76 MB | Measurement evidence. Only `tools/scaffold.py` reads it. |
| `output/` | 36 MB | Renders, regenerated by `make convert`. |
| `corpus/` | 14 MB | Reference PDFs downloaded from sars.ac.tz. Not ours to redistribute. |
| `templates/` (the rest) | 25 MB | **sdist only.** `src/mussannoni/resources/` already holds every shipped byte of it, so carrying both duplicated ~24 MB of identical font files. It could not regenerate those resources from an sdist anyway — that needs the excluded fixtures. |
| `bindings.yaml`, `calibration.json` | small | Provenance. `calibration.json` is consumed at *scaffold* time, not render time; its corrections are already baked into the fixture coordinates. |

One documented exception, in the **sdist only**: the reference PDF for `school_results` and the
render made from it, so the fidelity claim is demonstrable from the distribution alone.

```
corpus/MANIFEST.json                              sha256, page count, fetch timestamp
corpus/secondary/school-results.pdf               the reference    (15 pages, 900 KB)
output/secondary/school-results/rendered.pdf      our render       (15 pages, 2.5 MB)
output/secondary/school-results/report.json       its measured fidelity metrics
```

Nothing at runtime reads any of it — it is documentation. It is kept out of the wheel because the
wheel is what every application installs, and 3.5 MB of sample is pure weight for anyone who only
wants to render.

Resulting artifact sizes: **wheel 6.7 MB** compressed (28 MB installed), **sdist 9.3 MB**. Both are
nearly all fonts. Dropping the duplicated `templates/` took the sdist down 30% even after adding
the sample pair.

The sdist is for building and inspecting, not for running the workshop: with `corpus/`, `extract/`
and the fixtures absent, the measurement loop cannot run there, and the tests that need them skip
or fail. Use a git checkout for that. Building the wheel from the sdist does work, and is verified
on every `uv build`.

## `layout.json`: what a fixture becomes

A fixture is a *rendered-geometry* document: every glyph cluster carries an absolute offset and a
sub-point advance correction. That is what reproducing a reference requires and it is useless as an
input format. `tools/package_resources.py` reduces each one to the parts that generalise:

```json
{
  "page":   {"width_pt": 792.0, "height_pt": 612.0, "orientation": "landscape"},
  "table":  {"x_pt": 32.16, "y_pt": 29.28, "width_pt": 727.65, "columns": [20.88, 44.3, ...]},
  "header": {"row_count": 4, "height_pt": 94.8, "rows": [...], "labels": ["S/N", "WILAYA", ...]},
  "body":   {"row_height_pt": 9.36, "cells": [{"column": 0, "align": "right", "line_class": "t5",
                                               "top_pt": 4.365, "pad_right": 7.02, ...}]},
  "text_styles": {"t5": {"size_pt": 5.28, "base14": "helv"},
                  "t4": {"size_pt": 4.8, "fontfile": "fonts/BCDEEE-ArialNarrow-Bold-12.ttf"}},
  "rule":   {"width_pt": 0.48, "fill": "...", "header_d": "M597.22 94.7h0.48v28.92h-0.48Z..."},
  "rows_per_page": 28
}
```

Three decisions in there are worth knowing about.

**The body row shape is the modal one.** It is the most common cell shape across every body row of
every measured page, so a report's occasional sub-heading or totals band does not become the
prototype. Cells that span are skipped — a span is structure, not a repeating row shape. A few
reports have columns that are merged away in *every* measured row and therefore have no prototype
of their own; those borrow the report's modal shape rather than dropping the caller's data.

**The header band is kept verbatim, including its glyph corrections.** It is the same text every
time, so it keeps its measured fidelity. Overriding a header cell re-lays it out like a body cell,
which necessarily discards those corrections.

**Header rules are kept; body rules are redrawn.** The measured `rules` path holds absolute
coordinates for the reference's own row count, so the body's gridlines have to be regenerated for
whatever the caller supplies. The header's cannot be: its cells are merged into subject groups, so
drawing every column boundary across it would strike lines through the merged headings. The
segments lying wholly inside the header band are therefore emitted exactly as measured, in
`rule.header_d`.

## How generated text is positioned

The fixtures place each glyph cluster at the advance width recorded in the reference PDF. Those
corrections describe *one specific string*; reusing them for different text would smear the new
glyphs across the old advances. So generated cells emit a single run with no `chunks` and
`letter_spacing_pt: 0`, and the table layer positions it by **measuring** the string with the same
face MuPDF would use — the embedded font file where the report embeds one, otherwise the base-14
face that the bundled `Report Sans` / `Report Serif` fallbacks were exported from.

That is accurate to the font's own metrics, which is what the reference was typeset with. It is not
the same as reproducing a measured original glyph for glyph. For that, pass a full geometry
document to `render_document()`.

## Fonts and the redistribution question — CLOSED 2026-09-23

**The package ships no font derived from a proprietary one, and this is no longer an open gate.**
Every bundled face is redistributable and metric-compatible with the face it replaces:

| Replaces | Bundled face | Licence | Measured advance delta |
|---|---|---|--:|
| Arial | Liberation Sans | SIL OFL 1.1 | 0.0000 pt |
| Arial Narrow | Liberation Sans Narrow Bold | GPL v2 + font exception | 0.0000 pt |
| Calibri | Carlito | SIL OFL 1.1 | 0.0000 pt |
| Times New Roman | Liberation Serif | SIL OFL 1.1 | — |
| Courier New | Liberation Mono | SIL OFL 1.1 | — |
| Tahoma | Liberation Sans Bold | SIL OFL 1.1 | ≤ 0.7852 pt, one class in one report |

Measured per character over each replaced subset's own cmap. Twelve of the thirteen embedded faces
substitute **exactly**. The Arial subsets differ on `U+0640` and `U+2070`–`U+2079` only, and the
corpus uses 73 distinct characters with a highest codepoint of `U+2019`, so none of them appears in
any of the 46 reports. Tahoma has no metric-compatible open clone; it backs one text class.

Substituting blindly does *not* work and was measured: pairing everything with Liberation Sans Bold
gives errors up to **34.33 pt**, because the narrow faces are narrow and a subset returns notdef
advances for characters it lacks. Correct pairing is what makes it exact.

`tools/package_resources.py::_FONT_SUBSTITUTES` holds the mapping and rewrites both
`layout.json`'s `text_styles[*].fontfile` and each `report.css`'s `@font-face` src. The build
**fails** rather than shipping a face it has no substitute for, because `table._style_font` falls
back to base-14 silently and base-14 is not metric-compatible with Arial Narrow — the unnoticed cost
there is about 14 pt.

Also gone are the URW-derived base-14 faces previously exported from MuPDF as `report-*.otf`. They
carry MuPDF's own copyleft terms, which do not sit inside an MIT distribution, so `Report Sans` /
`Report Serif` / `Report Mono` are backed by Liberation.

Effect on size: the wheel drops from **8.5 MB to 4.3 MB**, font files from 92 to 10.

## Historic note: the redistribution question as it stood

Text classes name a licensed system face first and a bundled fallback second — `font-family: Arial,
'Report Sans'`. Arial and Times New Roman are **never bundled**; `make setup` installs them on the
rendering host, and without them the layout still holds because the fallbacks are metric-compatible
while the glyph outlines differ. `mussannoni doctor` reports what is available.

Per-report `fonts/` directories hold glyph subsets lifted out of the reference PDFs, several of
them derived from proprietary foundry faces (Tahoma, Calibri, Arial Narrow). **Embedding a subset
in a PDF is ordinarily permitted by those licences; redistributing the extracted font files inside
a software package is a different act and is not covered by this project's MIT licence.**

This is the one open gate before uploading to a public index. Resolve it by either confirming the
terms for each face, or building without those directories and letting the affected classes fall
back to `Report Sans` / `Report Serif`. Everything else about the distribution is ready.

## Keeping the package resources current

`src/mussannoni/resources/` is generated and committed, so building a wheel never needs the 257 MB
of fixtures. The risk of a committed generated directory is that it goes stale, so:

```sh
make package-resources   # regenerate after any change under templates/
make check-resources     # fail if the committed copy has drifted
```

`make check` runs `check-resources` between lint and tests, and
`test_packaged_resources_are_current` asserts the same thing from the test suite.

## Release

```sh
make build        # check-resources, then wheel + sdist into dist/
make dist-check   # twine check both artifacts
```

Then bump `version` in `pyproject.toml` and `__version__` in `src/mussannoni/__init__.py`
together — `test_version_matches_the_distribution_metadata` fails if they drift — record the change
in `CHANGELOG.md`, and upload with `twine upload dist/*`.

Note that the PyPI name `mussannoni` has not been claimed yet; check availability before the first
upload.
