# Rotated column-header placement fix for SARS PDF reproduction (v1)

Two placement bugs made vertical column headers (R/RANK, C/RANK, PERFORMANCE SUMMARY) land wrong on the rank reports the user flagged. `tools/tune.py` now refuses to write a rotated `by_face` calibration correction from a single sample — a lone rotated residual was ~1.8pt of noise from how PyMuPDF split one vertical string — and requires two corroborating samples both when writing and when reading. `tools/scaffold.py` `character_chunks()` became rotation-aware: rotated per-glyph reference offsets are negative (text climbing the page) while the font's advances are positive magnitudes, and the old code subtracted the two directly, doubling every offset and spreading each header to twice its height. Taking `abs()` of rotated offsets before computing per-glyph corrections fixes it. The whole corpus was then regenerated from a clean zero-base calibration and the README status table refreshed.

Watch for: (confirmed) the clean single-pass re-measure raises the *worst-span* text drift on a couple of already-failing horizontal-heavy reports (`region_council_performance` 0.54→1.746pt, `council_kata_rank_alama` 0.53→1.152pt) — this is a calibration-convergence artifact of the zero-base re-measure, not the rotated code touching the horizontal path, and those pages failed every gate before and after. (confirmed) No report reaches `done`: the binding gate corpus-wide is differing-pixels ≤0.5%, and every report sits at 2–14%, so the user's 100% pixel-identity goal remains bounded by the documented antialiasing jitter, not reachable by this change.

**Verdict**: APPROVED

## High-level view

The rotated calibration fix is a sample-count floor, not a threshold change. A rotated `by_face` entry is dropped unless at least two samples agree, and the same floor is applied at read time so any stale single-sample entry from an older calibration is ignored. Rotated runs still never borrow a horizontal `by_size`/`global` offset, so the rotation-keyed isolation that already existed is preserved. The floor is deliberately two, not the five used for `by_size`, because rotated headers are sparse (a handful per page) and five would discard every genuine rotated correction.

The `character_chunks()` fix is a one-line sign normalisation guarded by `rotation`; the horizontal path is byte-for-byte unchanged. `build_lines()` only threads `run.rotation` into that call. Nothing in the horizontal placement, letter-spacing, or fallback logic changed, which is what keeps the 29 improved / 0 regressed SSIM spread credible.

The Defect-3 "split heading" concern (PERFORMANCE SUMMARY arriving as three spans) was resolved without new grouping code: once each fragment's own origin is placed correctly, the three fragments already render contiguous because the reference positions them contiguously. No merge/ordering logic was added — worth knowing, since the feature plan proposed one.

The two horizontal worst-span drift outliers are the only thing that moved in the wrong direction, and they moved because FEAT-003 re-measured every report in one calibration pass rather than the multi-pass convergence the committed baselines had.

### Rotated `by_face` sample floor in tune.py

The defect was a rotated correction written from one sample. `residuals()` pairs reference and rendered spans by text and nearest position, then medians the residual per `(face,size,rotation)` key. Horizontal faces are kept at n≥1 (a single real measurement beats borrowing another face's offset), but a single *rotated* residual is dominated by how PyMuPDF fragments the vertical string — the committed `Arial-BoldMT|3.6|90 dx=-1.795 n=1` was pure noise applied at ~1.8pt. The new floor parses the rotation out of the key (`int(key.rsplit("|", 1)[-1])`) and skips writing rotated entries below `MIN_ROTATED_FACE_SAMPLES=2`.

`correction_for()` mirrors the floor at read time (`entry.get("samples")` below the floor → treat as absent) and then falls through to the rotation guard that returns `(0.0, 0.0)` rather than a `by_size`/`global` offset. The write-time `len(pairs)` and the read-time `entry["samples"]` are the same quantity — the stored `samples` is the `len(pairs)` of the render that wrote the entry — so the two floors are consistent. I confirmed no single-sample rotated entry survives anywhere under `templates/*/*/calibration.json` after the regen, so the read-time floor is now a defense against future/older files rather than something the committed state relies on.

The floor of two rather than five is justified in the code comment and by the data: the three 3.6pt PERFORMANCE-SUMMARY fragments measure -1.79/-1.67/-1.73, tightly clustered, so two agreeing samples already distinguish a systematic offset from a lone outlier, and demanding five would throw away every genuine rotated correction on these sparse headers.

One asymmetry worth flagging (Issue 2): the write path `continue`s past a sub-floor rotated key, which means if a later render measures a previously-good rotated face only once, the accumulated `old` correction is dropped from disk rather than carried forward. It does not bite the current corpus, but the cumulative model otherwise always preserves `old`.

### Rotation-aware per-glyph offsets in scaffold.py

Rotated char_offsets are negative and monotonically decreasing — e.g. `R/RANK` records `[0.0, -2.999, -4.196, -7.195, -10.193, -13.192]` — because for rotation==90 the extract axis is y and the glyphs climb the page. `character_chunks()` computes each glyph's needed correction as `offsets[index] - natural[index]`, where `natural` (from `font.text_length`) is always a positive magnitude. Subtracting a positive advance from a negative offset doubled the magnitude, which is the "header spread to twice its height" the comment describes. `if rotation: offsets = tuple(abs(offset) for offset in offsets)` makes the two comparable in magnitude before the per-glyph diff.

The regenerated `council-schools-rank` fixture confirms the effect: R/RANK, C/RANK, SUMMARY and PERFORMANC now carry per-glyph chunks in the ±0.03–0.04pt range instead of the previous `letter_spacing 0.0` with no chunks. The guard is `if rotation:`, so horizontal runs take the identical code path they did before — `git diff` shows the horizontal branch untouched and `build_lines()` only adds `run.rotation` as the new fourth argument.

### Split PERFORMANCE SUMMARY heading

The feature plan proposed grouping the three PyMuPDF fragments (E / SUMMARY / PERFORMANC) into one continuous heading. No such grouping was implemented, and none was needed: each fragment is placed at its own measured origin, and because the reference itself positions them contiguously (tops 2.38 / 3.91 / 7.51 in the regenerated fixture), correct per-fragment placement reproduces the continuous heading. This is the right call — measured position only, no literal text matching — but reviewers expecting new ordering code in `grid.py`/`build_lines()` should know the fix lands entirely through the placement correction above.

### Horizontal-text fidelity and the zero-base re-measure

The rotated changes are isolated to rotated code paths, so horizontal placement logic is unchanged. The worst-span drift increases on `region_council_performance` and `council_kata_rank_alama` trace to FEAT-003 deleting all `calibration.json` and re-running a single tune pass: both now show `iterations: 1` where the committed baselines had been iterated to converge. On `region_council_performance` the page reports `maximum_drift_pt 1.746` against `median_drift_pt 0.21` over 383 spans — a single outlier horizontal span, not a systematic shift. Both reports failed SSIM and pixel-delta before and after with zero passing pages, so no gate regressed. A second tune iteration would re-tighten the outlier; it is only cosmetic while pixel-delta is the binding gate.

### Gate posture and the 100% goal

`region_top_schools` is the illustrative case: SSIM 0.9815 clears the 0.98 gate, yet `pages_passing` is 0 because differing-pixels is 2.10% against the 0.5% gate. Every report sits in the 2–14% pixel-delta band, and the per-page diagnostics attribute ~99.9% of differing pixels to one-pixel antialiasing jitter. The user's literal 100%-identical aspiration is therefore bounded by the rasteriser, exactly as docs/01-fidelity.md states; this change is the correct, verifiable improvement on the rotated-header defect (29 reports improved worst SSIM, 0 regressed beyond 1e-4, 11/262 passing pages preserved) without relaxing any gate. Gates in `tools/compare.py` and `tests/test_fidelity.py` are unchanged; `corpus/` has zero modified files; `uv run ruff check` on the two changed files is clean.
